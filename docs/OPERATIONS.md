# AI Global 运营指南

本文用于编辑、研究、社区、会员和企业服务团队。所有对外内容与服务统一使用 AI Global / AI电商出海研究院品牌。

## 角色与责任

| 角色 | 主要职责 |
| --- | --- |
| admin | 用户角色、站点配置、线索权限、内容删除、数据导出 |
| editor | 资讯、知识、工具、案例、报告、活动与社区审核 |
| member | 个人资料、收藏、主题、评论、报名与投稿 |
| paid_member | 会员知识、模板、完整案例、课程资料与外部知识库入口 |
| partner | 经审核的生态伙伴资料、合作内容与需求对接 |

正式环境不要共享管理员账号；每人使用独立账号并启用多因素认证。

## 每日工作

1. 查看采集任务错误、来源健康度与待审核资讯。
2. 核验标题、原文、日期、来源、分类和摘要事实。
3. 处理社区举报、新用户主题和评论。
4. 查看 `service_leads`，在一个工作日内标记并首次联系。
5. 处理报告下载、活动报名、投稿与合作申请。
6. 检查首页公告、活动状态与失效外链。

## 每周工作

1. 编辑周报草稿，确认每个链接、来源与商业披露。
2. 选择本周编辑精选、深度内容和报告入口。
3. 更新知识路径中的新文章与过期说明。
4. 复盘服务线索来源、合格率、响应时间与常见问题。
5. 检查社区主题质量，邀请实践者补充上下文而非追求数量。
6. 抽查工具定价类型、地区可用性和中文支持说明。

## 每月工作

1. 更新支柱页面和内容集群缺口。
2. 运行 SEO/GEO 可见度基线，记录搜索、引用与品牌实体变化。
3. 审核作者资料、案例授权、合作披露和来源删除请求。
4. 导出并备份线索、会员和运营配置。
5. 清理过期活动、无效来源、失效链接和重复订阅。
6. 审查 RLS、管理员、API 密钥和依赖更新。

## 资讯审核 SOP

采集流程：

```text
RSS/API/官方博客/投稿
→ 标准化
→ external_id 与链接去重
→ pending
→ 编辑核验
→ published / archived
```

发布前检查：

- 原文可以正常访问，来源是预期主体。
- 标题没有扩大或改变原意。
- 摘要为合理长度，不构成全文替代。
- 时间、公司、产品和市场名称准确。
- 推断明确标记为编辑观察。
- 商业关系、赞助或联盟关系已披露。
- 分类、Canonical、原文链接与相关文章正确。

来源方提出修改/删除：先将内容设为 `archived`，保存请求与处理记录，再由管理员决定修订或删除。

## 知识内容 SOP

每篇内容必须回答：

1. 本文解决什么问题？
2. 适合谁？
3. 三条核心结论是什么？
4. 事实与方法来源是什么？
5. 适用边界与风险是什么？
6. 下一步可以采取什么行动？
7. 作者和更新时间是什么？
8. 最常见的两个问题是什么？

公开内容优先服务搜索与行业教育；会员内容应提供公开内容之外的完整模板、案例、工作表或互动价值。

## 案例与研究

- 未公开客户名称时使用“某行业/某类型企业”。
- 示范方案必须显示 `Sample Playbook / 示范方案`。
- 未获授权不使用客户 Logo、截图、营收、ROAS、排名或增长百分比。
- 报告占位页不得编造页数、作者、样本、数据或发布日期。
- 正式报告需要记录研究范围、来源、方法、局限和版本。

## 社区审核

默认规则：新用户主题和评论进入 `pending`。

允许：真实问题、经验复盘、工具比较、需求、合作和活动。

需要修改：上下文不足、利益关系未披露、标题夸张、外链过多。

直接拒绝：违法、侵权、骚扰、仇恨、欺诈、虚假招聘、恶意引流、泄露隐私、绕过平台规则。

对重复违规用户：警告 → 限制发布 → 禁言 → 封禁。重大风险直接封禁并保留证据。

## 会员管理

首期支持：

- 免费注册自动创建免费会员。
- 管理员在 `profiles.role` 和 `memberships` 手动开通付费会员。
- 兑换码或外部支付完成后人工/自动更新。
- 外部知识库、微信群、知识星球等入口由官网统一管理。

每次开通记录计划、开始/结束时间、外部参考和操作人。退款或到期后同步撤销访问权限。

## 企业线索 SOP

状态流转：

```text
new → contacted → qualified → proposal → won
                              └→ lost
```

- `new`：一个工作日内确认。
- `contacted`：已建立有效联系，记录时间与下一步。
- `qualified`：目标、决策人、预算/资源、时间和问题基本清晰。
- `proposal`：已提供范围、里程碑、责任与报价。
- `won/lost`：记录结果与原因，禁止为了报表长期停留在 proposal。

首次沟通不索取密码、支付信息或无关敏感数据。服务承诺以正式合同为准，不承诺确定排名或 ROI。

## 首页与推荐位

公告只保留一个主要行动，过期活动及时关闭。编辑精选同时考虑：行业重要性、可行动性、来源可信度、内容类型平衡与商业披露。

合作内容不能自动获得编辑精选；需要按相同质量标准审核并明确标注。

## Cron 与故障处理

正常计划：采集每 2 小时、日报每日、周报每周一。

故障排查：

1. 检查 Vercel Cron 日志与 HTTP 状态。
2. 401：核对 `CRON_SECRET`。
3. 503：生产环境缺少 `CRON_SECRET`。
4. 单一来源失败：暂停该来源，不扩大频率重试。
5. Supabase 写入失败：检查迁移、Service Role 和表字段。
6. 大量重复：先停采集，再检查 external ID、Canonical 和去重规则。

自动任务只能生成 `pending` 或 `draft`，不能绕过人工审核直接发布/发送。

## 发布检查

- `pnpm typecheck && pnpm lint && pnpm build` 全部通过。
- 核心路由、移动端导航、搜索和所有表单可用。
- 无环境变量时 Mock 模式可运行；生产环境 Supabase 可持久化。
- Sitemap、robots、RSS、Canonical、OG 与 JSON-LD 正确。
- 联系方式、报告、活动、会员入口和法律页面已替换。
- 生产域名、DNS、HTTPS、邮件 SPF/DKIM/DMARC 正常。
- 管理后台已启用服务端角色保护。

## 数据与安全

- Service Role 只存在于服务端环境变量。
- 导出线索后按权限存储，不通过公共群聊转发。
- 定期审查 RLS、管理员列表和过期密钥。
- 删除请求、举报和高风险内容保留处理记录。
- 数据保留期限应在正式法务政策中确定。
